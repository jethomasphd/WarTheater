# Paper 2 — The Direct Toll Is a Floor

**Civilian-facing targeting, health-system degradation, and mortality in the first 170
days of the 2026 US–Iran War.**

A complete, self-contained, fully reproducible public-health study built on the
[IranWar.ai Event-Level Research Dataset](../) v1.2 (Days 1–170), executing paper seed
**#4 (public health / indirect mortality)** of the dataset's research agenda. Designed for
a graduate-level public-health first authorship: every analysis uses the standard
behavioral-statistics toolkit (means comparison, correlation, regression, mediation,
moderation), and every number in the manuscript regenerates from one command.

> **Thesis.** Direct civilian mortality in this war was *regime-gated and front-loaded*
> (80% of deaths in the first 24% of days; per-strike lethality fell 95% between the
> initial campaign and the July resumption), and within days it was carried almost
> entirely by the *civilian-facing slice of the target set* (b = 2.07 per civilian-facing
> location, p < .001; military-facing tempo null; 68% of the tempo–mortality association
> mediated by target-set widening). As benchmark facility damage accumulated (31 → 307 →
> 309 facilities), the *marginal* strike–mortality slope steepened fivefold (interaction
> p = .006) — consistent with resilience erosion. The documented toll is a **floor**: at
> the literature-average 4:1 indirect:direct ratio it implies ~15,800–18,200 total deaths
> in Iran and ~15,000–21,500 in Lebanon. Casualty sources diverged up to **3.8×** — and
> the dashboard's own metric re-anchored by −63% in a day — yet the core result is stable
> across data-confidence weighting variants: the counter-technology, extended from data
> publication to data analysis.

## Reproduce everything (~1 minute)

```bash
cd ResearchData/Paper2
python3 -m pip install -r requirements.txt   # pandas, numpy, scipy, statsmodels, matplotlib
bash run_all.sh                              # regenerates panel + register + all tables + all figures
```

The analysis is **pinned to the frozen** `../releases/v1.2/iranwar_event_dataset.csv`, so
it reproduces identically regardless of later dataset releases. All bootstraps are seeded
(`SEED=42`); there is no network or wall-clock dependence. Point it at a different dataset
with `IRANWAR_DATASET=/path/to.csv bash run_all.sh`. Every curated constant (the register
audit, benchmark anchors, toll claims, WASH rows) is verified against the dataset at run
time by anchor-text assertion — upstream drift fails loudly.

| # | Finding | Evidence |
|---|---|---|
| 1 | Mortality is **regime-gated and front-loaded** | Major Combat: 79.6% of deaths in 23.5% of days; phase η² = .76; combat-vs-ceasefire g = 3.4 (`t01`, `t02`, fig1/4) |
| 2 | **Per-strike lethality collapsed 95%** | 15.4 → 0.7 Iranian deaths per strike location, combat vs resumption; Mann–Whitney p < .0001 (`t02_lethality`) |
| 3 | **Civilian-facing targeting carries mortality** | b = 2.07*** per civilian-facing location; military-facing b = −0.47 n.s.; NB2 IRR 1.62*** (`t03`) |
| 4 | Tempo–mortality association is **68% mediated** by target-set widening | indirect a×b = 1.02, bootstrap CI [0.60, 1.84], 10k seeded resamples (`t04`, fig5) |
| 5 | **Marginal lethality steepens with facility damage** | strikes × damage interaction p = .006; simple slopes 0.18 → 0.63 → 1.07 (benchmark curve; HSSI variant same direction, n.s.) (`t05`, fig6) |
| 6 | The direct toll is a **floor** | Iran 3,166–3,636 documented; 4:1 scenario → 15,830–18,180 total; Lebanon 14,965–21,540 (`t06`, fig7) |

## Scope & limitations

This is a within-case ecological study of one conflict from contested OSINT data. Direct-
death models cannot observe indirect mortality (that is Section 4.6's point); mediation is
associational decomposition; moderation is time-confounded effect modification; and the
21-event insult register is a trajectory proxy, not a damage census (WHO counted 307
damaged facilities by Day 39 — which is why every degradation model runs twice, the second
time on the benchmark-anchored curve). See manuscript §6 and `docs/METHODS.md` §7–9.
